# 게임 흐름 (game-flow)

## 화면 전환
```
[시작] ─이름 입력→ [월드 선택] ─선택→ [스테이지 목록] ─선택→ [게임] ─성공→ [결과 모달]
   ▲                    ▲  ▲                                   │              │ 다음/재도전/목록
   └──────── 🏠 처음 ────┘  └─────────────── ← 목록 ─────────────┘◄────────────┘
```

## 게임 화면 구성
- 좌: 문제 패널(학생용 문제문, 교재 원문 접기, 학습 목표 칩, 힌트 영역, 툴바)
- 우: 조작 패널(상태 표시줄 `aria-live`, 엔진 렌더 영역)
- 툴바: ← 목록 / 💡 힌트(0→3단계) / ↩ 실행취소 / 🔄 다시시작 / 📖 완전 해설

## 제출 기반 상태 흐름 (핵심 · v2)
1. 진입: 정답·최소횟수·모범경로·완전풀이는 **표시하지 않음**. 힌트(1~3)만 선택적 열람.
2. 학생이 입력/선택/조작/경로 이동/전략 플레이. 엔진은 **과정(processTable)** 을 기록.
3. **제출 버튼**(엔진별 문구)을 눌러야 `controller.submit()` 실행 → 채점.
   - 아직 제출 불가능하면(선택 안 함/게임 미종료 등) `notReady` 반환 → 안내만, 해설 미공개.
4. 제출 성공 시: `hasSubmitted=true`, `explanationUnlocked=true` → **정답 여부와 무관하게** 결과·해설 공개.
5. `Store.recordSubmission()` 로 시도수·힌트수·최소기록·`lastSubmission` 저장.
- **자동 제출 사용 안 함**: 조작 완료(목표 상태 도달)해도 자동 채점/전환하지 않고 반드시 학생이 제출.

## 제출 후 결과 화면(같은 모달에 순서대로)
1) 채점 결과(정답/일부 만족/재확인) 2) 내가 제출한 답+기록 3) 나의 풀이 과정표
4) 정답·성공 조건 5) 핵심 조건 6) 추상화 7) 단계별 풀이 8) 각 단계 이유
9) **나의 풀이 ↔ 모범/최적 풀이 비교(나란히)** 10) 자주 하는 실수 11) 더 효율적인 방법
12) 정보 개념 13) 점수 14) 생각 정리(서술) 15) 🔄 다시 풀기 / 다음 문제 / 완전 해설

## 힌트/해설 규칙
- 힌트 1(관찰 질문)·2(핵심 조건 하나)·3(다음 행동 한 단계). **최종 정답·전체 경로·최적 횟수·완성 계산식 미포함.**
- 완전 정답과 풀이 과정은 **제출 후에만** 공개(교사 모드는 예외로 즉시 열람).
- '완전 해설(제출 후)' 버튼은 제출 전 비활성화.

## 다시 풀기 / 재열람
- 다시 풀기: 입력·조작 초기화(새 시도). 이전 제출 기록은 보존.
- 새로고침 후에도 스테이지 목록의 **📖 해설 다시 보기**로 제출 문제 해설 재열람.

## 기록(localStorage)
`player`, `settings{sound,motion,teacher}`,
`records{id:{cleared,submitted,explanationUnlocked,bestScore,attempts,hintsUsed,minMoves,minTime,reflection,lastSubmission,lastPlayed}}`
